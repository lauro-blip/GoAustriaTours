# CLAUDE.md: GoAustriaTours

Google Ads landing site for **GoAustriaTours** (Austria tours: Self Drive, Escorted, Coach; US travellers, USD).
Server-rendered Laravel 12 app. Keep this file a map, not a manual. **Update it when you change anything it describes.**

## Stack
Laravel 12 (PHP 8.2+), Blade (no SPA), Vite, MySQL (SQLite only in tests). PUBLIC site: hand-written CSS scoped under `.t3` (`resources/css/home.css` + `inner.css`) and plain JS (`resources/js/home.js`); fonts Playfair Display (headings), Inter (body), JetBrains Mono (small labels), self-hosted from `public/fonts/` via `@font-face` at the top of `home.css` (Inter + Playfair preloaded in `layouts/site.blade.php`). ADMIN only: Tailwind CSS v4 (`resources/css/app.css`), Alpine.js (+ focus plugin, `resources/js/app.js` via `admin.js`), Trix editor.
Custom admin at `/admin` (no Filament). The old public fonts (Helvetica / Apoc Revelations LT / Cormorant) are no longer used on the public site; Cormorant stays only for the admin.

## Run on XAMPP (Windows)
```
composer install && npm install
php artisan key:generate && php artisan migrate --seed && php artisan storage:link
npm run build        # or: npm run dev
php artisan serve    # http://127.0.0.1:8000   (fallback: php -S 127.0.0.1:8000 -t public server.php)
```
Full detail: `docs/reference/LOCAL_XAMPP.md`. Tests: `php artisan test` (in-memory SQLite, never touches MySQL).

## Business rules that are not obvious from the code
- **Consent**: every form has a REQUIRED, unticked checkbox with the exact wording in `App\Support\Consent` (legal company name comes from the `legal_company_name` setting). Enforced in browser AND server (`consent` => `accepted`). The exact text shown, terms version, timestamp, IP, user agent and page URL are stored on each enquiry. Changing the wording requires sign-off and a bump of `terms_version` in `config/goaustria.php`.
- **reCAPTCHA v2** checkbox on every form, rendered explicitly (several per page, also in the modal), verified server-side, **fails closed** (including Google unreachable). Local `.env` uses Google's public test keys.
- **One endpoint, three form shells**: every form posts to `EnquiryController@store` (same consent, honeypot `website`, reCAPTCHA, 5/min + 20/hour per IP): the hero quiz (`hero-quiz`), the quote popup (`header-modal`, opened by any `[data-quote]` link, package cards add `data-package-id`) and the inline forms on inner pages (`pages/partials/quote-form.blade.php`: `contact`, `package-quote`, `ask-question`). Never fork the validation. Errors/old input are scoped by `form_name`.
- **Travel date** is a native date picker (`<input type="date" data-date>`, min today, max +3 years) on the popup and inline forms; the server validates `Y-m-d` and stores "F j, Y" (e.g. "June 15, 2027"). Optional.
- **Phone is REQUIRED on every form** (all five, incl. ask-question). The country select puts its dial code in the field (`resources/js/phone.js`, inputs marked `data-phone`; it also switches the country when a number with another code is pasted) and checks the number live. The server has the final say in `EnquiryController@store`: libphonenumber `isValidNumber` for the chosen country + `App\Support\PhoneQuality::isPlaceholder` (all-same digits, 1234567890-style runs, repeated blocks, 555-01xx fiction). Keep `phone.js` and `PhoneQuality` in step. Stored as E.164 in `phone_e164`.
- **Quiz** steps/options live in `quiz_steps` / `quiz_options` (admin: Quiz). Final contact step is built into the component. Default steps live in `QuizSeeder::steps()` (also applied by migration `2026_11_25_000070`): season, group size (1-20, 21+), nights (1-20, 21+), flights, budget, likelihood, age range; destination + travel style are switched off (re-enable in Admin > Quiz). Icons are thin-line keys in `components/icon.blade.php` (add new ones to `QuizController::iconNames()` too); options without an icon render as serif text tiles. A privacy line ("We never sell or share them") sits under the quiz. Without JS the plain form shows. Answers are stored as JSON (human labels) on the enquiry.
- **Tracking**: `CaptureTracking` middleware stores first touch + last touch (UTMs incl. the Google Ads `utm_device` / `utm_adposition` / `utm_adcreative`, gclid, gbraid, wbraid, referrer, landing page) in 30-day cookies; saved on the enquiry. GTM only renders when the `gtm_id` setting is set. dataLayer events: `enquiry_submit` (on submit) and `enquiry_thank_you` (thank-you page).
- **GoHighLevel is OFF** whenever the token or location ID is empty. Both are set in Admin > GoHighLevel (`Admin\GhlController`; token stored ENCRYPTED in `settings`, never shown back, with a read-only "Test connection"); values saved there override `GHL_API_TOKEN` / `GHL_LOCATION_ID` in `.env`, which remain the fallback (resolved in `GhlClient::resolvedToken()` / `resolvedLocationId()`). Changing `APP_KEY` makes a saved token undecryptable, so re-enter it. Field names are defined ONLY in `GhlFields`; matched by exact name. First-touch CRM fields are never overwritten; last-touch fields always update. The sync never blocks or fails an enquiry; failures are recorded on the enquiry and retryable from admin. Tests force-blank the GHL env in `phpunit.xml`.
- **Google Sheet log**: every enquiry is also appended to a Google Sheet, one tab per form (`SheetRow::TABS`), every stored field as a column (incl. all UTM / click-ID first + last). `SyncEnquiryToSheet` job -> `SheetsClient` -> an Apps Script web app (`docs/reference/google-sheet-script.gs`, set-up in `docs/reference/GOOGLE_SHEET.md`). URL + secret (encrypted) live in Admin > Google Sheet (`Admin\SheetsController`), `.env` `GOOGLE_SHEET_WEBHOOK_URL` / `GOOGLE_SHEET_SECRET` is the fallback. OFF when either is empty; never blocks the enquiry; status on each enquiry (`sheet_status`), retry in admin, backfill with `php artisan sheets:sync`. If you add an enquiry column, add it to `SheetRow::row()`.
- **Placeholders**: contact details, prices, testimonials, legal text and images are placeholders. Never invent business facts. Use `[CONFIRM: ...]` and list them in `docs/reference/CONTENT_TO_CONFIRM.md`. Public pages must never show one: `$site` settings, FAQs and prices holding `[CONFIRM` are hidden or replaced ("Price on request", plain modal heading); unconfirmed hero/Why claims (best price, review rating, pricing promise, bonding) are removed from the views until real wording exists. Page/tour-type/package text from the database is still shown, so edit it in Admin.
- Legal pages are starter templates only, not legal advice.

- **Header menus** (`layouts/site.blade.php`, desktop from 1100px; accordion-free mobile menu): Destinations (the trigger is a link to `/destinations` that also opens the mega menu, class `mtrig`; region cards with journey counts, places from `config('goaustria.nav_places')`, promo card), Austria Vacations (trigger links to `/austria-vacations`, class `mtrig`; tour type cards with counts), Travel Style (trigger links to `/travel-styles`, class `mtrig`; `config('goaustria.travel_styles')` -> `/packages?style=slug`, decided by `App\Support\TravelStyles`), About Us (about, journal, testimonials, terms, privacy), Contact. Destinations shows region photos, popular places and a featured journey card (`$navFeatured`, the first featured published package); Travel Style cards show journey counts (`$navStyles`); both come from the composer. The trigger for the current section is gold. About Us is a mega menu too: links with one-line descriptions + legal links, the latest journal post (`$navPost`) and a get-in-touch panel. Panels are as wide as the page content (1270px), start at the header edge and close after a short grace delay; Escape closes one (JS in `home.js` also sets `aria-expanded`). The mobile menu (`layouts/nav/mobile.blade.php`, styles "Mobile menu v2" at the end of `home.css`) has a sticky logo + close bar and an accordion (one open at a time): Destinations = region cards with photo and journey count + popular places chips + All destinations; Austria Vacations = tour type cards (photo, tagline, count) + Compare / All journeys; Travel Style and About Us = rows with descriptions and counts; then the quote button, phone and "Free quote · No obligation". Menu photos are tiny `public/images/winter/{name}-240.webp` thumbnails (lazy, so they load only when a submenu opens; make one for any new region / tour type photo). While open the page behind does not scroll (`html.m-lock`) and Escape closes it. Nav data (`$destinations`, `$tourTypes`, `$pkgCounts`, `$navPlaces`, helpers `$w`, `$img`) comes from the `layouts.site` view composer in `AppServiceProvider`. The old "Vacations & Experiences" menu (signature collections, By Traveler) was dropped; `/packages?collection=` and the `traveler` field still work server-side.

- **Consult bar** (bottom of every page except package, contact, thank-you): phone number + "Request a quote" (opens the popup). On mobile it shows only a phone icon (when a real phone is set) + the Request a quote button. Pages that need their own bottom bar or a form pass `noStickyBar`.

- **Optional tracking IDs** (Admin > Trust & tracking): Microsoft Clarity, Google Ads tag (+ conversion label, fired on the thank-you page) and Meta Pixel load only when filled in. Leave Google Ads/Meta blank if GTM handles them.

## Conventions
- Admin > Settings (`SettingController`, groups in `GROUPS`) and Admin > Trust & tracking (`TrustController extends SettingController`, groups in `TRUST_GROUPS`) share one save/validate routine; add a field to the right `GROUPS` array. Trust & tracking owns phone, phone_tel, email, the planner fields, `established_line`, `trust_mark_N_*`, `review_*` and `gtm_id`.
- Settings are read with `Setting::get('key')` (cached; flushed on write). Public views receive `$site` (settings; `[CONFIRM` values blanked) from a view composer; `layouts.site` also gets the nav data.
- New simple admin list: extend `Admin\CrudController` (model, routeName, title, columns, fields, rules) and add a `$crud(...)` line in `routes/admin.php`.
- **Visual editor (Admin > Pages, round 1)**: split screen with a live preview of UNSAVED changes. `Admin\PagePreviewController` (POST `admin/pages/{page}/preview`, `admin/pages/preview` for new pages) renders the real public view with `editing => true` (passed as view data, never shared globally) and appends `admin/pages/_preview-overlay` (hover outlines, click-to-select, inline text editing, links disabled). In editing mode `blocks/_all` wraps each block in `<div data-blk="i" style="display:contents">` and `$ed('field.path')` adds `data-edit` to plain-text elements; on public pages both output nothing (a test checks no editor markup reaches visitors). The editor (`page-builder.js`) posts the form to the preview (debounced), scales the iframe for desktop 1280 / tablet 820 / mobile 390, syncs selection both ways via postMessage, applies inline edits to the block data, and keeps undo/redo snapshots (Ctrl+Z / Ctrl+Shift+Z outside text fields). When adding a new text field to a block template, add `{{ $ed('field') }}` to its element so it is editable on the page. **Version history**: every save that changes something stores the previous version in `page_revisions` (`Page::snapshot`, last 30), restorable from the editor sidebar (a restore is itself undoable).
- **Visual editor round 2**: every normal block has Style options (`Blocks::styleFields()`, grouped under "Style" in the editor): background light/tint/navy/photo (+ `bg_image`, shown as `--blk-bg` with a navy overlay), spacing, content width, heading alignment, show on all/desktop/mobile. `Blocks::styleClasses()` turns them into FIXED classes (`blk-sp-s|l`, `blk-w-n|w`, `blk-hl`, `blk-hide-m|d`, `blk-dark blk-photo`; CSS "Section style options" in `inner.css`), defaults add nothing; never emit per-section CSS. **Columns** block (`blocks/columns.blade.php`): layouts `Blocks::LAYOUTS` (1, 2 equal, 2 wide left/right, 3, 4; stacks under 760px), column elements defined in `Blocks::elements()` and rendered from `resources/views/blocks/el/{heading,text,image,button,list,quote,spacer,video}.blade.php`; field kind `columns` is cleaned by `Blocks::cleanColumns` (max 4 columns x 12 elements). Element headings start at h3 under a section heading, at h2 without one. Videos are click-to-load (`data-video`, handled in `home.js`; YouTube privacy mode / Vimeo dnt via `Blocks::videoEmbed`). Block views must keep `class="sec blk ... {{ $tone }}"{{ $sx }}` on their root section. The home page loads `inner.css` only when it contains inserted (non-home) blocks.
- **Admin > Menus** (`Admin\MenuController`, `App\Support\Menus`, Alpine `menuEditor` in `resources/js/menu-editor.js`, view `admin/menus.blade.php`): header items (built-ins `home|destinations|vacations|styles|about|contact` can be renamed/reordered/hidden but never removed; custom links), header button label + link (empty link = quote popup), footer CTA defaults (pages can still pass `ctaTitle`/`ctaText`), footer columns (built-ins `contact|destinations|styles|brand` + custom link columns), brand text, bottom bar links, copyright (`{brand}`/`{year}`), consult bar texts. Saved as JSON in settings `menu_header` / `menu_footer`, cleaned by `Menus::cleanHeader/cleanFooter` (links via `Blocks::cleanLink`). The mega menu panels live in `resources/views/layouts/nav/{destinations,vacations,styles,about}.blade.php`; `layouts/site` loops `$menuHeader` / `$menuFooter` (from the layout composer) for the header, mobile menu and footer.
- **Admin > Design** (`Admin\DesignController`, `App\Support\Design`, view `admin/design.blade.php`): colours (5 contrast-checked presets + 9 colour fields), heading/body font (self-hosted or system fonts only), button shape, heading case, body weight. Saved as `design_*` settings (only values that differ from the brand). `Design::css()` prints a `<style id="site-design">` in `layouts/site` overriding the `.t3` variables ONLY when something differs; Playfair preloads are skipped when it is not the heading font. "Preview on the site" stores the unsaved design in the admin's session (banner on the site), returning to Design loads it into the form. Because of this, never hard-code brand colours in public CSS: use `var(--navy|--dark|--accent|--accent-d|--ink|--cream|--tint|--line|--ice)` and `color-mix(in srgb, var(--dark) 55%, transparent)` for transparency (all old rgba/8-digit hex brand colours were converted).
- Public brand colours/fonts live ONLY in the variables at the top of `.t3` in `resources/css/home.css`; the admin has its own tokens in `app.css` (`@theme`).
- Typography: section headings (`.h`, `.pk-h`) are 44px on desktop (768px and up) and 32px on mobile and body text is Inter weight 300 (set on `.t3`; hero sub is 400 for readability on photos). Change them only at the end of `home.css` / `inner.css`. Fixed sizes, no shrink-to-fit: headings wrap naturally (balanced) and the italic part sits on its own line.
- Never use `@if` directly after a word with no space in Blade (it is not parsed). Never nest `<noscript>`.
- Uploaded images go through `ImageService` (validated, WebP, 480/960/1600 widths). Alt text is required.

## Gotchas
- Public fonts are plain `@font-face` rules pointing at `/fonts/*.woff2` (copied from Fontsource; on the server `public_html/fonts` must be a symlink to `laravel_app/public/fonts` like `build` and `images`). Admin Cormorant is still imported from Fontsource in `app.js`, NOT in CSS: Tailwind v4 inlines CSS `@import`s and breaks the font `url()` paths on Windows.
- Performance rules (Lighthouse mobile 90+): `inner.css` is its own Vite entry, loaded by `layouts/site.blade.php` on every page except home; do not import it from `home.js`. Carousel CSS lives in `home.css`. Below-the-fold sections use `content-visibility: auto`, except the last section in `main` (as a 720px placeholder it overlapped the footer CTA). Hero slides 2 and 3 use `data-src` and load after `window load`. No layout shift on load: the inline `qjs` script in `layouts/site.blade.php` lets CSS show only the hero quiz's `.q-start` step from the first paint (the full form used to collapse when JS ran: desktop CLS 0.97). Results and open items: `docs/reference/SEO_CHECKLIST.md`.
- Headless Chrome cannot render windows narrower than 500px: check mobile layouts at 500px.
- `public/robots.txt` must not exist; robots is generated by `SeoController`.
- After changing views/config on a server, run `php artisan optimize:clear`.
- Windows PowerShell 5.1 `-Encoding utf8` writes a BOM which breaks PHP files; write files with the editor tools instead.
